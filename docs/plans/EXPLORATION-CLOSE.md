# 探索闭环补齐方案

对应 FR02/03/04，并补 FR11 的主动结束。范围：当前 60 SKU 的场景探索，不声称全品类、新品发现或市场实时性。

1. 任务对话页增加“随便看看”，生活改善、新奇发现可同时选择；方向卡保持浅底、墨色和绿色的原有编辑式布局，不改变纵向商品推荐页。
2. 复用 Turn：exploration_action + expected_mission_version；start/feedback/next/select_for_purchase/end。反馈只有明确点击才保存，neutral 撤销。每轮最多三方向；目录场景和商品证据决定可用方向，已否定方向不主动返回，耗尽明确结束。
3. api_threads 的 JSONB 保存探索状态，api_turns 保存幂等请求及已提交状态投影；状态与任务同事务。先幂等再版本检查，沿用 Mission 锁协调审批。Worker 将结构化状态投影为事件，不调用模型完成这些确定性按钮动作；正常购买仍调用原 Agent。
4. 选方向后同会话进入购买、递增版本、清空候选/比较/旧审批，保留清单和待购。明确询问预算，不把兴趣当硬约束或自动写购物清单。结束保留历史，不冒称取消旧任务。
5. 验收：无预算开始、证据、反馈/撤销/去重/耗尽、重发/版本冲突、伪造方向/用户隔离、转换与旧审批、PG重建恢复及Android UI/API流程。fake 与真实模型结果分开；未执行的设备或真实模型验收不标通过。

本批不会调用付费模型、提交、推送或继承历史发布 GO。
