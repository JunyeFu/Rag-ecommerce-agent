# V3 复杂电商业务修复方案

版本：2026-09-22  
目标：在不把产品退回“淘宝首页 + 商品瀑布流”的前提下，让 Agent 能处理一线电商用户常见的复杂购买任务。

## 一、前端设计不可破坏的约束

1. 一级入口仍然只有 `任务 / 决策 / 我的`。
2. `任务` 保持单一连续工作台：用户说需求，Agent 分析，先给主推荐，再通过纵向滑动查看次推荐、再次推荐。
3. 不新增商城首页、分类瀑布流、订单、支付、客服、营销频道。
4. Agent 只展示公开执行阶段和结果依据，不展示思维链。
5. 演示商品、演示报价和真实商业事实必须视觉分层，不能用一张商品详情卡暗示可购买。
6. 所有写入和外部跳转继续使用原生确认面板；取消必须保持无写入。
7. 复杂能力通过任务约束、决策工作台和底部抽屉表达，不把十几个业务按钮塞进主推荐卡。

## 二、修复优先级

### P0：让复杂需求能够被正确理解

#### 1. 任务解析与约束编辑

用户可以直接输入：

> 给我配一套 5000 元以内的办公设备，显示器必须 4K，耳机优先降噪，周五前送到公司。

后端返回结构化 `ShoppingMission`：

- `items[]`：品类、数量、收货对象。
- `hard_constraints[]`：预算上限、规格、送达截止时间、商家限制。
- `soft_preferences[]`：品牌、外观、权重。
- `unknowns[]`：仍需澄清的字段。
- `budget_allocation`：总预算和分项预算。

Android 不展示 JSON，而在任务页顶部显示紧凑的约束条：

`总预算 ¥5000` `4K 硬约束` `周五前送达` `耳机优先降噪`

每条约束可点击编辑；编辑后显示“重新计算推荐”，不自动覆盖原结果。

验收：10 个复杂黄金任务中，品类拆分、硬/软约束和待澄清字段解析正确率 ≥ 90%；不能解析时必须显示明确澄清问题。

#### 2. 澄清采用结构化轻问答

保留对话输入，但优先提供选项芯片：

- `预算是否可超出 10%`
- `必须官方/自营`
- `周五前送达是否硬约束`
- `接受相近替代`

用户仍可自由输入。选项只是减少表达成本，不改变 Agent 的工具权限。

验收：澄清后 Mission 约束可见；未回答的字段不会被静默猜测。

### P1：让推荐结果支持多商品决策

#### 3. 主推荐纵向流升级为“任务段落”

保持当前卡片视觉，不改为商品列表：

- 主推荐：显示整套方案或当前最关键商品。
- 次推荐：显示替代方案。
- 再次推荐：显示预算/规格妥协后的方案。
- 每张卡新增 `满足的硬约束`、`牺牲的偏好`、`证据状态`。

多商品任务在主推荐顶部增加“方案总览”，只显示数量、预算占用和未满足项；具体商品仍按纵向候选卡展开。

#### 4. 比较工作台修复

将卡片中的 `加入比较` 改为真正的用户选择：

- 默认不勾选；Agent 推荐理由不等于用户已选择。
- 达到 2 个候选后，底部出现 `比较已选 2 项`。
- 决策页以横向对比表展示统一字段、硬约束、价格状态和风险。
- 支持“按预算 / 按硬约束 / 按偏好”重新排序。

验收：用户未点击时比较数量为 0；只点击两项时比较表只出现两项；刷新和恢复后选择状态不丢失。

### P1：补足真实业务事实，但维持演示边界

#### 5. 报价、库存、配送和售后统一为事实卡

新增 `BusinessFact` 字段：

- `fact_type`: price / inventory / delivery / merchant / after_sales。
- `verification_level`: `DEMO_FIXTURE` / `DISCOVERY_ONLY` / `FEED_VERIFIED` / `LIVE_AUTHORIZED`。
- `observed_at`、`expires_at`、`evidence_ref`。

前端显示：

- 演示：`演示数据 · 不代表可购买`。
- 真实：`已核验 · 更新时间 ...`。
- 过期：`报价已过期 · 重新询价`。

没有 LIVE 来源时，不显示“现货”“明日送达”“官方正品”等确定性文案。

#### 6. 缺货与替代方案

当硬约束无法满足时，Agent 必须分为：

1. 严格方案：满足硬约束但可能超预算。
2. 预算方案：满足预算但放宽软偏好。
3. 替代方案：明确指出改变了哪一项约束。

禁止直接把不同规格商品当作同款替代。

### P2：形成持续任务能力

#### 7. 价格追踪、补货和复购

在 `决策` 页增加“观察任务”而非营销入口：

- `低于 ¥800 时提醒我`
- `补货时提醒`
- `按上次方案重新询价`

需要后端持久化观察条件、最近一次检查时间和触发记录。当前没有定时任务和通知渠道前，按钮必须显示“演示观察，不会后台提醒”，不得伪装成已启用。

#### 8. 待购计划和购物车明确分层

- 待购计划：保存意图和候选，不代表库存锁定。
- 购物车：只有接入真实平台写入后才能出现。

当前版本只保留待购计划，不新增“去结算”“提交订单”等假按钮。

## 三、接口与数据改造

新增/扩展接口：

- `POST /v1/missions/parse`：自然语言转结构化 Mission。
- `PATCH /v1/threads/{thread_id}/constraints`：编辑约束并创建新计算版本。
- `GET /v1/threads/{thread_id}/comparison`：返回用户明确选择的候选。
- `POST /v1/threads/{thread_id}/reprice`：重新询价，保留旧证据。
- `POST /v1/threads/{thread_id}/watchers`：创建价格/补货观察任务；没有调度器时只允许 fixture 模式。

所有候选、事实和观察任务必须带 `mission_id`、`version`、`evidence_ref`；不能把状态只存在 Android 内存。

## 四、分步实施顺序

1. **C1 Mission 解析（已完成）**：结构化多商品、硬/软约束、澄清字段；`POST /v1/missions/parse`、`mission_updated.mission` 与 `ThreadSnapshot.mission` 共用同一解析结果。
2. **C2 Android 约束条（已完成）**：任务页与推荐页展示结构化约束；点击约束进入整句编辑，保存后只标记待重算，用户明确点击“重新计算推荐”才持久化新版本并重新运行 Agent，不改变主推荐布局。
3. **C3 比较选择（已完成）**：候选默认不选；用户选择通过线程比较接口持久化并随快照恢复；决策页只显示所选候选，提供横向事实表及按预算、硬约束、偏好三种显式排序。
4. **C4 事实卡（已完成）**：报价、库存、配送、商家、售后使用类型化事实与独立证据等级；Android 推荐卡明确显示演示/发现/第三方核验/授权核验状态，没有 LIVE 来源时不输出确定性承诺。
5. **C5 替代编排（已完成）**：检索结果类型化输出严格、预算、替代三条路线；不可成立的路线显式标记不可用，预算方案不得违反硬约束，替代方案必须绑定不同商品或规格并列出放宽项。路线随事件和线程快照恢复，Android 在主推荐纵向叙事上方展示路线状态。
6. **C6 待购与观察（已完成）**：Android 待购页只显示服务端 `/v1/cart` 已持久化的报价，不再把全部检索报价误当待购；价格/补货观察以 owner/thread/offer 为范围持久化为 `DEMO_DRAFT`，固定 `scheduler_active=false`，界面明确“不会后台提醒”。
7. **C7 真实使用验收（已完成）**：Playwright/API 简单、中度、重度场景 3/3 通过；Android 真实 API/SSE 黄金任务 8/8、单任务恢复 1/1、Compose 前台回归 28/28 通过；ADB 坐标点击验证恢复后继续任务与新建独立 Mission。验收中发现并修复了“新需求沿用旧线程”和小屏核心按钮不可点击两项真实缺陷。

C1-C7 验证：复杂品类拆分 10/10；Runtime/API 全套 120 passed（12 个 integration 用例按标记排除），临时 PostgreSQL 迁移/漂移检查及集成套件 4/4 通过；Playwright Agent 业务套件 3/3；OpenAPI 与三端生成契约无漂移；Android Java 21 单元/编译通过，真实 API/SSE 黄金任务 8/8、单任务恢复 1/1、完整前台套件 28/28 通过。

## 五、验收门槛

### 接口

- 多商品 Mission 可解析并持久化版本。
- 硬约束满足率 ≥ 0.90；未满足项必须显式返回。
- 推荐、事实、报价均有 EvidenceRef 和验证级别。
- 比较选择、待购写入、重新询价幂等；取消确认无写入。
- 禁止把 fixture 报价升级为 LIVE。

### 视觉与操作

- 首屏仍是“需求 → Agent 分析 → 主推荐”，不出现商城首页元素。
- 主/次/再次推荐可连续上下滑动，当前层级始终可见。
- 未选择商品不会自动进入比较。
- 复杂任务的约束可以在任务页被看见、编辑和重新计算。
- 演示价格、真实价格、过期价格有明确视觉差异。
- 高风险写入和外部跳转都有确认面板。
- 进程重启后 Mission、约束版本、比较选择和待购状态一致。

### 业务场景

至少通过：单品、套装、预算优先级、规格变体、送达期限、缺货替代、正品/售后、比较决策、价格观察九类任务；真实联盟报价、支付和订单继续标记为外部门禁。

## 六、明确不做

本修复阶段不增加：商城首页、营销推荐流、多 Agent、支付订单、物流系统、生产 OAuth、真实联盟结算、Kafka/Kubernetes，以及没有实际消费者的通用防御层。
