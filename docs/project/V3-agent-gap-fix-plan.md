## 缺陷与修复方案

| ID | 优先级 | 已核实差距 | 修复与验收 |
| --- | --- | --- | --- |
| D01 | P0 | `list.update`、`cart.update` 只返回成功标记，未调用清单或待购状态写入；持久化实现继承了同一工具处理器。 | 将工具参数映射到现有领域写入，使用 `context` 的用户身份；审批后由 Agent 写入，随后通过公开 API 刷新可见；拒绝与重复执行不产生额外写入。 |
| D02 | P0 | 报价结果有 `price_minor`、`shipping_minor`、`availability` 等字段，但工具证据只声明商品标题、品牌、品类和属性。 | 报价证据明确覆盖金额、商家、库存、来源和采集/失效时间；缺失证据时不输出已验证报价；分别测试 `DEMO_FIXTURE` 与第三方演示级别。 |
| D03 | P1 | 默认 `DemoProvider` 使用固定四步读链；真实 Provider 也强制部分读链。现有约束保护事实，但对澄清、重新询价和后续动作的自主选择覆盖不足。 | 保留事实读取和权限边界，增加目标驱动的澄清、工具选择、失败后重规划与审批恢复场景；冻结黄金场景中至少 8/10 经真实 Provider 完成预期流程。 |
| D04 | P1 | 持久化演示仍继承 `DeterministicEmbeddingProvider`；真实 Embedding 类未进入主检索组合。 | 在显式真实检索模式接入真实 Embedding 与 Qdrant 投影；fixture 模式继续确定性运行；保留 BM25、向量、融合消融与来源证据。 |
| D05 | P2 | 弱权威第三方查价目前是独立沙箱连接器，未进入 Agent 报价和 Android 展示链。 | 接入独立 `THIRD_PARTY_DEMO` 报价路径，保留来源与时效；不可用时显示明确失败，不冒充 `LIVE` 或本地 fixture。凭据可用性是外部依赖。 |
| D06 | P1 | Android README 仍写四入口，当前代码为三入口；历史验证文件仍写 Java 17，现行工具链为 Java 21；V3 基线发布状态也落后于当前发布矩阵。 | 更新当前说明和证据索引；历史验证记录保留原样并标注历史时点；README、任务包、实际代码和运行方式一致。 |
