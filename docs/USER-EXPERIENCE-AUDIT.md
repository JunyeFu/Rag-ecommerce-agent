## 一、用户操作功能全景

### 1.1 三大入口模态

| 模态 | 入口 | 后端端点 | 状态 |
|------|------|---------|:---:|
| 文本对话 | 首页输入框 | `POST /api/v1/chat` (SSE) | ✅ |
| 语音输入 | 首页麦克风图标 | `POST /api/v1/voice/chat` (SSE) | ✅ |
| 拍照找货 | 首页相机图标 | `POST /api/v1/upload/vision-search` (SSE) | ✅ |

### 1.2 对话中可执行操作（自然语言驱动）

| 操作 | 触发示例 | 后端处理 |
|------|---------|---------|
| 商品推荐 | "推荐一款降噪耳机" | classify -> retrieve -> rerank -> generate |
| 条件筛选 | "200元以下的蓝牙耳机" | slot 提取 (price_max + category) -> 过滤检索 |
| 多轮追问 | "要轻量一点的" | conversation_history 继承槽位 -> 细化检索 |
| 否定排除 | "不要红色，排除小米" | exclusion_rules + SQL NOT 过滤 |
| 场景化推荐 | "去三亚度假买什么" | scenario.py LLM 映射品类 + MMR 多样性采样 |
| 商品对比 | "对比前两款" | compare 节点 + Template Method 管线 |
| 追问澄清 | "推荐个..." | clarify 节点 + ClarifyEvent chips |
| 购物车查看 | "看看购物车" | cart 节点 -> cart_service |
| 加购 | "把第一个加入" | cart_nlp 序号解析 + rag_retrieve 兜底 |
| 改数量 | "买3件" / "加2件" | 中文数字解析 + 增量更新 |
| 删除 | "不要第三个" | 序号解析 + remove |
| 清空 | "清空购物车" | cart_service.clear |
| 下单 | "确认下单" | 弹出确认页（**不创建真实订单**） |
| 联网搜索 | "xxx是什么" | web_search 节点 + DuckDuckGo |

### 1.3 REST 操作（页面驱动）

| 模块 | 操作 | 端点 |
|------|------|------|
| 商品 | 浏览/筛选/搜索/详情 | `GET /products` + `GET /products/{id}` |

## 三、后端能力边界与交互缺陷

### 3.1 对话 Agent 不能做的事

| 缺失能力 | 影响 |
|---------|------|
| 对话中直接下单 | "下单"只弹出提示，不创建真实订单 |
| 修改订单地址/备注 | 创建后不可改，只能取消 |

| # | 严重度 | 缺陷 |

### 4.4 三大概念-实现落差（按影响排序）

#### 落差 1：商家知识库上传（F6）完全缺失 — 核心差异化卖点落空
- **概念**：PRD F6(P0) + 差异化策略第 1 条 + "商家上传文档即可拥有专属导购"
- **实现**：`knowledge.py` 仅 15 行 stub，`ingestion.ingest_document()` 标注"预留"未接 API
- **影响**：项目从"可定制知识库的导购 Agent"退化为"固定 287 条商品的导购 Agent"

#### 落差 2：内容安全过滤（F10）+ 可解释引用（F7）双缺失
- **概念**：F10(P0) 要求双重安全过滤 + safety_check 节点；F7(P0) 要求 `[1][2]` 引用标注
- **实现**：app 目录全量搜索 `safety/moderation` **零命中**；生成输出无 citation 字段
- **影响**：合规风险（法规要求）+ 信任建设落空（可解释性卖点无代码支撑）

#### 落差 3：检索精度 P@3 = 0.146 vs 目标 0.75
- **概念**：PRD §10.3 规定 P@3 ≥ 0.75、NDCG@5 ≥ 0.80
- **实现**：IMPROVEMENT-DESIGN 记录 P@3 = 0.146（差 4.8 倍）
- **根因**：Ground Truth 按 rating 排序（非语义标注）、Hybrid Search 实为纯向量、287 条商品嵌入空间稀疏

### 4.5 9 场景体验落差

| 场景 | 预期 | 实际 | 落差 |
|------|------|------|------|
| 拍照找货 | VLM + CLIP + 属性 + RRF 多路检索 | VLM -> 文本 -> 单路检索 | 多模态深度不足，丢失视觉向量直接匹配 |
| 商品对比 | 差异自动高亮（颜色区分） | 仅表格渲染，无差异高亮 | 视觉差异化缺失 |
| 推荐场景 | 回答带 `[1][2]` 来源引用 | 纯文本 + 卡片，无引用标注 | 可解释性削弱 |
| 评价晒单 | 评价图片可展示 | 媒体存 BLOB 无读取端点 | 前端无法展示评价图片 |

## 五、总结

### 项目特征画像

**"广度超预期、深度有缺口"**：
- ✅ 实现了 9 场景 + 26 前端页面 + 15 API 模块 + 231 单元测试

- ⚠️ 2 个创新卖点（可解释引用、自信度标注）未落地
- ⚠️ 前端 9 个设置项空实现 + 4 个个人页占位 + 3 个订单功能占位
