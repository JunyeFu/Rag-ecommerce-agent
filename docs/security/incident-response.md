# 安全事件响应手册

## 分级与立即动作

- P0：凭据泄漏、跨用户数据访问、未批准的外部导航/写操作、供应链接管。立即停用相关连接器或写工具，隔离流量，冻结发布并保全脱敏审计。
- P1：可重复 SSRF/redirect 绕过、删除失败、敏感日志、可利用高危依赖。24 小时内确定所有者和缓解；未关闭不得进入 live。
- P2/P3：无直接利用链的加固项，进入有期限任务包且不得被平均分掩盖。

## 操作顺序

1. 记录事件 ID、首次发现时间、运行版本、受影响边界与证据哈希；不要复制 live secret。
2. 通过策略关闭最小受影响能力：连接器、`link.resolve`、媒体类型、运营写操作或整个 Agent。
3. 撤销/轮换必须由凭据所有者执行；本地开发者不得读取旧值来“验证”。
4. 查询脱敏 Trace、幂等审计和连接器状态，确认影响窗口与用户集合。
5. 修复后运行安全回归、依赖/容器扫描、集成与 live canary；保留失败记录。
6. 由安全、业务、法律和发布所有者分别确认恢复。发送方 PASS 不能代替接收方验收。

## 恢复门槛

P0/P1 根因关闭、回归加入、受影响凭据已由所有者轮换、数据主体/监管通知决策完成、独立复核通过后方可恢复。若任何证据不可用，状态为“未获取/阻断”，不得解释为无事件。
