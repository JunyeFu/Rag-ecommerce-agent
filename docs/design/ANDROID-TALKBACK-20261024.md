# TalkBack 输入、遍历与激活收尾（2026-10-24）

本轮遵循用户“先完成不依赖 Docker 的部分”的选择。当前验收结果及逐次记录见 [证据 JSON](../evidence/v3/android-talkback-20261024.json)。不将本轮 HTTP 内存 fixture 结果写成 PostgreSQL 持久化、真实模型或完整产品发布验收。

## 已定位的问题与修复

| 编号 | 观测与根因 | 最小修复及验证 |
|---|---|---|
| TB-01 | 旧测试用 shell 注入按键，没有产生实际 TalkBack 焦点推进；少量标签计数及直接设置焦点不能证明可用 | 改用 Android SDK EmulatorController 的硬件键盘／多指触摸；系统设置页先做输入对照，再在 MainActivity 观察实际焦点事件。观察器不执行节点点击或设置焦点 |
| TB-02 | 探索选项的 Checkbox 与相邻文字分别进入遍历，产生两个相同名称的目标 | 整行成为一个有名称、48dp 的 toggleable；清除子控件重复语义。200% fixture 先失败（2 个目标）后通过，实际 TalkBack 检查可切换且没有多余文字目标 |
| TB-03 | 推荐页顶部整个区域可滚动，返回按钮也被滚出；选完候选后无法自然返回对话 | 固定返回／标题／连接行，仅条件区内部滚动；总高度仍不超过240dp。200% fixture 先证明返回不可见，再验证固定后可见／可点击；原生路径验证纵向推荐后返回决策 |
| TB-04 | 主机固定等待450ms后采样，TalkBack自动滚动后的焦点尚未稳定，遗漏“随便看看”等真实已到达目标 | 等待实际焦点事件与当前原生节点的名称、类型、边界一致；页面仍可能需要用户真实两指滚动，不能用设置焦点代替 |
| TB-05 | 固定650px手势不足以翻过实际候选视口；恢复页在大字号下按钮不一定首屏可见 | 使用原生可滚动区域的80%相对距离；大字号恢复时实际滚动并激活“继续任务”，保留原失败 |
| TB-06 | 测试在首次连接／恢复完成前判断输入页；随后真实恢复结果覆盖页面，导致寻找“例如”失败 | 启动后等待实际连接／恢复标识，再从恢复页通过真实手势进入任务；不注入新任务或成功状态 |
| TB-07 | 一次原生观察器返回0个测试且最后窗口为空，旧脚本丢弃错误原因；现有日志已无法复原准确异常 | 保留该次失败，不将它记为产品通过；后续观察回执增加退出码和最多24行原生失败摘要。后续同版成功不能反推原始失败原因 |

## 代码范围

- 产品：`EditorialShoppingApp.kt`，只有探索单目标语义与推荐页固定返回布局属于本次改动；这些文件已有更早的用户改动，不能把整个 Git diff 归于本轮。
- fixture：`ShoppingFlowTest.kt` 新增两个针对已观察问题的200%回归；此类测试允许构造状态，但不算原生业务端到端通过。
- 原生观察：`TalkBackTraversalTest.kt` 仅采集已安装 TalkBack 的焦点／窗口／点击事件与原生节点，保留系统无障碍服务。
- 主机：`verify_android_talkback.py` 和 `emulator_hardware.py`。通过有临时认证的127.0.0.1 SDK gRPC发送硬件事件；临时发现凭据只在内存读取，不进入证据。

## 证据分层

1. 两个红→绿 fixture 证明具体产品缺陷及修复，不代替真实 TalkBack。
2. 最终 APK 的原生路径验证触摸／键盘、默认／200%字号、三入口、弹窗及候选主流程。输入来自硬件事件；只有文本编辑沿用 Android 输入，不以它证明 TalkBack 激活。
