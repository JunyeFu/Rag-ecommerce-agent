# V3-ANDROID-UX-CLOSE-01 易错点

- 不得把“按钮点击成功”当作用户审批；先确认，再写入。
- 不得只在客户端禁用按钮；服务端仍需校验状态、幂等键和报价有效性。
- 不得把 `DEMO_FIXTURE`、source ref 或 API 状态原样当普通用户文案。
- 不得用通用“Agent 已完成”覆盖澄清、失败、过期和恢复状态。
- 不得让比较候选数量脱离真实复选状态或自动把三张卡全部标记为已选。
- 不得用视觉截图证明接口写入正确；必须同时保留请求/事件序列。
- 不得用接口 200 证明视觉可用；必须检查真点击、动态字体和 TalkBack 语义。
- 不得将重试实现为静默重复写入；确认、重连和恢复都必须保持幂等。
- 不得把真实报价、联盟授权或生产发布结论写进本包的 fixture 证据。
