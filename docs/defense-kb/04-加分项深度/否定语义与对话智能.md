# 否定语义与对话智能

> 评委问："'不要XX' 这类否定怎么处理？多轮对话怎么记住上下文？" → 此页

## 否定语义处理 ⭐⭐

### 三层过滤架构

```
用户输入: "推荐防晒霜，不要含酒精的，不要日系品牌"
  │
  ▼
① 意图层 — 否定提取
   触发词: "不要" / "除了" / "非" / "不含" / "排除"
   解析: exclude_terms = ["酒精", "日系"]
   代码: apps/backend/app/services/intent.py
  │
  ▼
② Qdrant 向量层 — must_not 过滤
   品牌维度: must_not = ["资生堂", "花王", "雪肌精", ...]
   属性维度: must_not = ["含酒精", "酒精成分"]
  │
  ▼
③ 文本层 — 兜底过滤
   title + highlights 包含排除词 → 丢弃
   代码: apps/backend/app/services/exclusion_rules.py
```

### 验证结果（5/5 100%）

| 输入 | 排除结果 |
|------|:--:|
| "不要骨传导的" | ✅ 0 款骨传导 |
| "不要华为" | ✅ 0 款华为 |
| "不要入耳式的" | ✅ 0 款入耳式 |
| "不要白色的" | ✅ 0 款白色 |
| "除了小米" | ✅ 0 款小米 |

## 多轮上下文记忆 ⭐

### 状态持久化

- PostgreSQL `sessions` 表：`session_id → state_json → message_count`
- 每次对话完成自动保存状态
- 下次请求时自动恢复上下文

### 对话历史继承

```
第1轮: "推荐耳机"     → category=耳机, 存入 state
第2轮: "要降噪好的"   → 继承 category=耳机, 追加 feature=降噪
第3轮: "300以内"      → 继承 category=耳机+降噪, 追加 price_max=300
```

### 品类切换自重置

```
当前: category=耳机, feature=降噪
用户: "换个品类，看看手表"
  → 自动重置 feature=降噪, 切换 category=手表
  → 避免耳机偏好污染手表推荐
```

## Agent 主动反问 ⭐

### 触发条件

用户输入信息不足以定位具体品类/价格/场景时，Agent 主动追问：

```
用户: "推荐一款手机"
  → 信息不足: 无预算/无偏好/无场景
  → Agent 反问: "更看重拍照、续航还是性价比？"
  → 用户选择后继续检索
```

### 实现

- LangGraph `node_clarify` 节点
- ClarifyEvent SSE 事件 → Android 反问 UI（Chip 选择按钮）
- LLM 失败时模板降级（"请告诉我您的预算范围和偏好"）

> 代码路径：`apps/backend/app/services/agent.py` — node_clarify
> `apps/backend/app/services/voice_recognition.py` — ASR 语音转文字
