# 性能优化实践

> 评委问："性能做了什么优化？有具体数据吗？" → 此页

## 优化全景

| 优化项 | 手段 | 效果 |
|--------|------|------|
| LRU 查询缓存 | 高频查询结果缓存 + cache_key 多轮感知 | **12s → 16ms** (750x) |
| 意图分类加速 | Doubao fast path（LLM 替代关键词规则） | 准确率提升 + 延迟稳定 |
| Reranker 预热 | lifespan 启动时加载模型 | 消除首次 2s 冷启动 |
| 异步流水线 | 意图分类 + 检索并行执行 | 节省 ~200ms |
| SSE 交错流式 | 文本+卡片交替推送 | 感知延迟降低 |
| Embedding 本地化 | BGE 模型本地加载 | 无网络往返 |

## 1. LRU 查询缓存

```
cache_key = hash(user_query + conversation_id + filters)
  ┌──────────────┐
  │  用户查询     │
  └──────┬───────┘
         ▼
  ┌──────────────┐     命中 (15-25%)
  │  LRU 缓存    │────────→ 16ms 直接返回
  └──────┬───────┘
         │ 未命中 (75-85%)
         ▼
  ┌──────────────┐
  │  正常 RAG    │────────→ 12s → 结果写入缓存
  └──────────────┘
```

> 代码：`apps/backend/app/services/cache.py`

## 2. TTFT 与首屏响应

| 指标 | 值 | 说明 |
|------|:---:|------|
| SSE 首事件 (first_event) | **47ms** | 首 SSE progress 事件，后端在 LLM 调用前即发送 |
| SSE 首文本 (first_text) | **47ms** | 前导 text_delta，客户端即刻显示 |
| LLM 首 Token (TTFT) | **~1.5s** | Doubao streaming first chunk |
| 首商品卡片 | **~6-10s** | 随 text_delta 交错推送 |

> SSE 首事件 47ms 确保用户感知"系统已响应"，后续 LLM 生成流式到达

## 3. Reranker 预热

```python
# apps/backend/app/main.py — lifespan
@asynccontextmanager
async def lifespan(app):
    # 启动时预加载 Reranker 模型
    preload_reranker()  # ~2s, 仅一次
    yield
```

## 4. 异步流水线

```
同步模式:  intent(200ms) → embedding(80ms) → qdrant(15ms) → rerank(900ms) → generate(1.5s)
               总计 ~2.7s (不含 LLM 生成)

异步模式:  intent(200ms)
                ↘
                embedding(80ms) → qdrant(15ms) → rerank(900ms) → generate(1.5s)
                      总计 ~2.7s（异步不阻塞其他请求）
```

## 5. SSE 交错流式

旧格式：全部文本 → 全部卡片 → done（用户等待到末尾才看到商品）
新格式：摘要 → (商品文本 + 卡片) × N → 结语（边看文本边出卡片）

> 感知延迟：用户约 2s 看到第一张商品卡片
