# AI 辅助开发说明

> 字节跳动 AI 全栈挑战赛明确要求：**可用 AI 工具辅助开发，但答辩需能解释原理和代码细节**
> 比赛推荐工具：TRAE IDE（字节官方 AI 编程工具）

## 本项目 AI 工具使用策略

### 使用工具

| 工具 | 用途 | 覆盖范围 |
|------|------|---------|
| **Claude Code** | 主力 AI 编程助手 | 架构设计建议、样板代码生成、文档整理、Bug 排查 |
| **TRAE IDE** | 字节推荐工具 | 部分 Android Compose 布局辅助 |
| **手动编写** | 核心链路 | Agent 编排、反幻觉机制、SSE 协议设计 |

### 分模块 AI 参与度

| 模块 | AI 参与度 | 说明 |
|------|:---:|------|
| LangGraph Agent 编排（agent.py 3049行） | **20%** | 节点定义/条件路由/状态结构 — 手动设计；代码骨架 AI 辅助 |
| 意图分类（intent.py 16740行） | **30%** | 9类意图定义 — 手动；38对品类关键词推理 — AI 辅助扩展 |
| RAG 检索链路（retriever/reranker/embedding） | **10%** | 检索逻辑 — 手动；API 调用样板 — AI 辅助 |
| 反幻觉机制（Prompt 禁止清单 + 校验层） | **10%** | 全部手动设计，AI 仅辅助格式化 |
| SSE 交错流式协议 | **15%** | 协议设计 — 手动；解析器实现 — AI 辅助 |
| Android 24 Screen Compose UI | **50%** | 页面结构/交互逻辑 — 手动；Composable 布局样板 — AI 辅助 |
| 数据模型（Pydantic/Kotlin data class） | **60%** | 字段定义 — 手动；样板代码 — AI 生成 |
| 文档（28篇 .md） | **40%** | 核心内容 — 手动；格式/索引/交叉引用 — AI 辅助 |

### AI 使用原则

1. **架构决策必须人来定** — AI 提供选项和理由，最终选型由我决策
2. **核心链路必须人写** — Agent 编排/反幻觉/SSE 协议/否定过滤 均为手动设计
3. **AI 生成代码必须逐行审核** — 样板代码也不例外
4. **能解释每一行的原理** — 这是答辩红线

### 答辩应对

**如果评委问："你用 AI 写了多少代码？"**

回答要点：
- AI 是效率工具，不是替代思考——我用它生成 Compose 布局、Pydantic Schema 等样板代码
- 核心设计决策和链路逻辑是我独立完成的——Agent 7 个显式主节点 + 条件路由、反幻觉三层防护、SSE 交错协议
- AI 辅助了约 30-40% 的代码量，但关键路径 100% 由我设计和审核
- 我可以解释项目中任意一行代码的设计意图和实现原理

**如果评委问："为什么不用 TRAE？"**

回答要点：
- 我用了 TRAE 辅助部分 Android Compose 布局
- 主力使用 Claude Code 因为它在复杂架构推理和跨文件重构方面更适合本项目
- TRAE 在 Compose UI 生成方面表现不错，两个工具互补使用
