# 降级与容错

> 评委问："出错了怎么办？服务崩了用户看什么？" → 此页

## 降级策略矩阵

| 故障场景 | 降级方案 | 用户感知 |
|----------|---------|---------|
| LLM 超时 (>30s) | 自动重试 1 次 → 降级提示"服务繁忙，请稍后重试" | 友好提示，不卡死 |
| Qdrant 不可用 | curl 预热检测 → Docker 重启 | 后端启动时自愈 |
| SSE 断流 | 缓存命中直出（16ms） | 瞬间返回，无感知 |
| 图片识别失败 | 降级提示"请手动描述商品特征" | 引导文字输入 |
| Cart 非 UUID 格式 | 400 + 中文提示 "商品ID格式错误" | 明确错误原因 |
| BGE Embedding 冷启动 | 首次调用预热 5s | 仅首次用户感知 |

## 缓存降级机制

```
用户查询 → 缓存命中?
  ├── 是 → 16ms 直接返回（跳过 LLM 调用）
  └── 否 → 正常 RAG 链路 → 结果写入 LRU 缓存
```

> 缓存 key 含 conversation_id，多轮上下文感知，防止不同对话串缓存

## 错误处理原则

- **FastAPI 全局异常处理器**：统一捕获未处理异常，返回结构化错误 JSON
- **LLM 调用重试**：`llm_client.py` 含指数退避重试（max 1 次）
- **Clarify 节点降级**：LLM 生成追问失败时，模板降级（"请告诉我您的预算范围和偏好"）
- **旧格式兼容**：缓存返回无 `[PRODUCT_N]` 标记的旧响应时，自动降级为旧格式（全部文本→全部卡片）

## 后端启动自检

```bash
# deploy.sh 自动执行
1. Docker Compose 启动 3 容器
2. 健康检查轮询（curl /health）
3. ensure_qdrant_data() 检测数据完整性
4. 全部通过后标记 READY
```

## 演示风险预防

| 风险 | 预防措施 |
|------|---------|
| 网络不稳定 | 后端 + 数据库本地 Docker 部署 |
| LLM API 限流 | TPM 800K / RPM 700 充足 |
| 演示设备问题 | 预编译 APK 直接安装（24.1MB） |
| 数据丢失 | 种子数据脚本可重复执行 |
