# V3 Android Agent 前端与业务行为缺陷审计

- 日期：2026-09-22
- 状态：OPEN，待按优先级修复
- 范围：Android `com.ragcommerce.agent`，Mission → 推荐 → 决策工作台 → 待购集合
- 审计方式：Pixel_9 模拟器上的 ADB 真点击、UIAutomator 树、截图、实现代码和公开电商 Agent 资料交叉审阅
- 当前证据目录：`output/adb-real-click-20260922/`

## 1. 结论

当前版本已经具备可识别的 Agent-first 视觉方向：用户输入任务，系统给出主推荐、次推荐、再次推荐，再进入比较和待购集合；没有恢复为传统商城首页、分类瀑布流或订单支付页。视觉语言统一，主推荐层级清楚，纵向分页也符合本项目已经确认的“主推荐 → 次推荐 → 再次推荐”交互。

但业务语义仍没有完全跟上视觉。当前更像“把 Agent 结果做成编辑杂志卡片”，而不是可被用户信任、可控、可恢复的购物 Agent。最高风险不是颜色或装饰，而是：

1. 写入待购集合在当前点击路径中直接成功，没有出现用户可理解的确认/审批上下文；
2. 内部证据、fixture、API 和运行态字段直接暴露在消费界面，价格真实性与可购买性不够醒目；
3. Agent 的澄清、进度、依据、失败恢复和重新询价能力没有形成可操作闭环；
4. “比较”看起来像一个状态标签，尚未成为真正可读、可操作的决策工具。

因此，页面设计方向可保留，交互和文案需要收口；不建议再增加商城化入口。

## 2. 可复核的当前流程

1. 任务页显示 `SHOPPING MISSION`、`把需求交给 Agent 决策`、在线状态、任务输入框、图片/语音和发送按钮。证据：`ui-14-task.xml`、`screen-14-task.png`。
2. 输入 `Aural Audio Quiet 01` 后，推荐页显示 `Agent 推荐`、`Agent 已完成`、主推荐和三张候选卡。证据：`ui-07-after-send.xml`、`screen-07-after-send.png`。
3. 主推荐卡展示商品图、满足项、风险、来源、价格、`DEMO_FIXTURE`、`加入比较`、`保存方案` 和 `加入待购集合`。证据：`ui-07-after-send.xml`。
4. 点击加入待购后，页面变成 `已加入 API 驱动的待购集合`，没有出现解释商品、商家、数量、报价新鲜度和撤销的确认面板。证据：`ui-08-approval.xml`。
5. 上滑可看到 `次推荐` 和 `再次推荐`，三张卡重复同一套操作按钮。证据：`screen-09-secondary.png`、`screen-10-again.png`。
6. 再进入决策页，可看到 `3 个候选`、已保存方案和待购集合；页面没有展示可横向/纵向读取的关键规格对比，也没有明显的刷新报价、删除或修改数量动作。证据：`screen-13-decisions.png`、`ui-13-decisions.xml`。

## 3. 缺陷清单

### P0：写入语义与用户承诺不一致

**现象**：`加入待购集合` 直接调用远端购物车写入，并在成功后显示“已加入 API 驱动的待购集合”。当前点击证据没有出现审批弹层。实现位置：`ShoppingViewModel.kt:196-206`、`ShoppingRepository.kt:389-405`。

**影响**：用户无法确认加入的是哪一个商家报价、数量是多少、报价是否仍有效；“待购集合”是可逆规划动作还是已接近购买动作也不清楚。Agent runtime 虽然有 approval checkpoint，但这个卡片按钮绕过了它。

**修复方案**：

- 把按钮改为“加入待购”并先打开原生确认面板；面板显示商品、商家、价格、运费、数量、报价采集时间和“仅保存计划，不下单”。
- 确认后才调用写入 API；取消不改变远端状态；成功后提供“已加入 · 撤销”短时操作。
- 若报价过期或状态不是 `CURRENT`，按钮变为“重新询价”，禁止直接写入。
- 将 Agent runtime 的审批事件和 UI 写操作统一到同一条状态链，加入幂等键与重复点击测试。

**验收**：未确认时 API 写入次数为 0；确认后恰好 1 次；取消/返回/旋转屏幕后不产生写入；刷新决策页后状态一致。

### P1：商业事实与内部字段混入消费文案

**现象**：卡片直接展示 `DEMO_FIXTURE`、`来源 demo:v3:...`、`来源 ${sourceRef}`；决策页还使用 `DECISION WORKBENCH`、`WAITING LIST`。实现位置：`EditorialShoppingApp.kt:624,651,669,716,720,983`。

**影响**：用户需要理解内部验证枚举和数据主键，且容易把 `¥399.00` 误认为可购买的实时价格。当前有演示声明，但它分散在 Agent 状态和“我的”页面，不在价格旁形成第一视觉层级。

**修复方案**：

- 面向用户改为“演示报价 · 不可购买”“采集于 2026-09-22 09:13”“来源与依据”；原始 ref 放入可展开的“查看证据”抽屉。
- 价格旁固定展示验证级别、商家、库存未知/可用和有效期；没有这些字段时显示“未核验”，不渲染看似精确的金额。
- `DECISION WORKBENCH`、`WAITING LIST` 仅保留为小号品牌装饰或移除，主标题使用“比较方案”“待购计划”。
- 对 `DEMO_FIXTURE` 增加全局一次性说明，不在每张卡重复暴露枚举值。

**验收**：普通用户不需要知道 `DEMO_FIXTURE` 才能理解价格；任何金额旁都能看到“演示/实时”和采集时间；原始 source ref 不出现在首屏。

### P1：Agent 过程不可见，澄清能力没有形成前端闭环

**现象**：提交后很快跳到“Agent 已完成”，没有可操作的“理解需求 → 检索 → 核验证据 → 比较候选”进度；契约已有 `clarification_required` 分支，但任务页没有看到澄清问答控件。

**影响**：用户不知道 Agent 是否理解预算、用途、排除项，也不能在检索前纠正约束；失败时只能看到通用错误，不知道下一步应补充什么。

**修复方案**：

- 把四个阶段做成公开状态条，展示当前阶段、已完成阶段和可取消操作，不展示思维链。
- `clarification_required` 渲染为问题卡和结构化选项，同时保留自由输入；用户回答后继续同一 Mission。
- 显示“本次使用的硬约束/软偏好/未确定字段”，允许修改后重新运行。
- 失败状态提供明确的重试、补充信息和回到任务入口，不用 `Agent 已完成` 覆盖失败原因。

**验收**：至少一个缺失预算场景会真实进入澄清；澄清前不会产生推荐写入；断线恢复后阶段和最后一条用户输入仍可见。

### P1：推荐卡有视觉层级，没有决策信息密度

**现象**：主、次、再次推荐以全屏纵向分页呈现，商品图占据较大空间；三张卡使用几乎相同的通用理由、风险和按钮。决策页只显示候选数量和缺失字段数量，没有规格差异表。

**影响**：用户可以“翻卡”，却难以回答为什么主推荐优于次推荐；对 3C 这类规格驱动商品，比较被迫转移到记忆和来回滑动。

**修复方案**：

- 保留纵向主线，但在卡片顶部增加“推荐理由摘要”：预算匹配、硬约束覆盖、关键差异、代价/风险各一行。
- “加入比较”改为明确的选择状态，并显示已选数量；默认只选主推荐，不能让“比较工作台 3 个候选”与复选框状态冲突。
- 决策页提供同屏的 3–5 个关键规格行、差异高亮、排序依据和“只看差异”；移动端使用纵向表格/对比抽屉，不做难以横向阅读的宽表。
- 每个候选卡保留“为什么不是另一个”或“未满足项”，避免三个通用理由。

**验收**：用户无需回到推荐页即可识别三个候选的关键差异；选择状态和比较数量一致；比较只引用已返回事实，缺失字段显式显示。

### P1：保存和待购缺少可见反馈与管理动作

**现象**：点击再次推荐的“保存方案”后按钮仍显示“保存方案”，没有就地成功状态；决策页虽出现已保存条目，但用户无法从当前卡片知道是否成功。待购集合只显示商家、价格和运费，没有数量、移除、更新报价和撤销。

**修复方案**：

- 保存按钮具有 `未保存/保存中/已保存/失败` 四态，成功后按钮变为“已保存”并支持取消保存。
- 待购集合增加数量、报价时间、过期状态、移除、重新询价和打开安全商家链接；打开外部链接前显示商家和 URL 域名确认。
- 决策页显示待购条目数量徽标和最近更新时间；空状态提供回到当前 Mission 的入口。

**验收**：每个写操作都有就地结果；刷新/重新进入后状态不丢；删除和重新询价真正调用 API 并可验证。

### P2：文本、按钮和信息架构需要收口

不应在普通用户首屏展示或作为主操作的内容：

- `API 驱动`、`source_ref`、`demo:v3:*`、`DEMO_FIXTURE` 原始枚举；它们属于证据抽屉或“数据说明”。
- `DECISION WORKBENCH`、`WAITING LIST`、`SHOPPING MISSION` 等英文系统标签；保留品牌化小眉题可以，但不能取代中文动作含义。
- “保存方案”和“加入待购集合”同时出现但没有解释两者差异；应改成“保存候选”和“加入待购计划”，并在首次使用时给出一句解释。
- 推荐卡中重复的“下滑查看次推荐”等提示；分页指示器和自然手势已经足够，保留一处轻提示即可。

建议补充但不放大为主按钮的能力：查看证据、查看关键规格、重新询价、修改约束、撤销、报告结果不符合预期。

### P2：页面设计合理性判断

**应保留**：

- 任务/决策/我的三入口，避免重新长出商城首页、订单和支付体系；
- 黑底、荧光绿、编辑化大标题的视觉识别；
- 主推荐 → 次推荐 → 再次推荐的纵向渐进结构；
- 决策页将比较和待购计划分开，避免把“加入计划”误导成“下单”。

**应调整**：

- 推荐页减少装饰占屏，把首屏空间让给价格真实性、关键匹配、风险和下一步动作；
- 决策页减少巨大标题和空白，增加可扫描的规格差异和条目操作；
- 底部导航图标必须和语义一致，并补充 TalkBack content description/testTag；
- 在线、演示、失败、恢复不能只靠颜色和一句状态文字，应有结构化状态组件。

## 4. 与先进电商 Agent 的差距

公开资料显示，Rufus 的定位不只是生成推荐，还包括产品发现、比较、价格决策和执行动作；Google Shopping 的 Agentic Shopping 强调用户给出品牌/预算条件后，只有满足条件才执行购买，并提供对比表、价格、库存等决策信息。见 [Amazon Rufus 官方介绍](https://www.aboutamazon.com/news/retail/amazon-rufus-ai-assistant-personalized-shopping-features)、[Google Universal Cart 与 agentic shopping](https://blog.google/products-and-platforms/products/shopping/google-shopping-cart/)、[Google AI Shopping 更新](https://blog.google/products-and-platforms/products/shopping/agentic-checkout-holiday-ai-shopping/)。

本项目当前已经覆盖“自然语言任务、推荐、比较、计划写入”的外形，但缺少先进 Agent 的三项关键体验：

1. 条件不完整时先问清楚，而不是直接完成；
2. 推荐结果以对比事实和新鲜度支撑，而不是只给漂亮卡片；
3. 任何外部/持久化动作在满足条件后仍由用户明确批准。

Baymard 的移动电商研究也指出，移动端用户容易因页面缺少整体概览、产生迷失、误触和重要内容被视觉结构遮蔽而中断；其规格驱动商品研究建议提供有效比较能力，但移动端比较应避免把用户困在宽表或被遮挡的比较面板中。见 [Baymard 移动电商 UX 趋势](https://baymard.com/research-articles/mobile-app-ux-trends)、[Baymard 规格商品比较](https://baymard.com/research-articles/provide-comparison-features)。这直接对应当前“大图+大标题占屏、比较信息不足”的问题。

## 5. 分层收口方案

### 第一阶段：交易与事实正确性（P0/P1，先做）

1. 统一保存、待购、重新询价和商家跳转的状态机；写入前确认，写入后可撤销。
2. 将报价真实性、采集时间、商家、库存和有效期放在价格同一视觉层级。
3. 清理内部枚举和原始 ref 的首屏暴露，增加证据抽屉。
4. 增加 UI/API 联动测试：取消不写入、确认只写一次、过期报价不允许加入、刷新后状态一致。

### 第二阶段：Agent 可解释与可恢复（P1）

1. 接通澄清问题、阶段进度、可取消、失败重试和 SSE 恢复。
2. 显示硬约束、软偏好、未确定字段和每个推荐的满足/未满足原因。
3. 增加重新询价、修改约束后重跑和从决策页回到 Mission 的路径。

### 第三阶段：移动决策效率（P1/P2）

1. 保留纵向推荐，但把“推荐理由/关键差异/风险/价格事实”压到首屏。
2. 将比较工作台改为移动友好的差异清单或底部抽屉，并保证复选状态真实驱动候选数量。
3. 缩减英文装饰标题、重复手势提示和无业务价值的巨大留白。
4. 为 TalkBack、动态字体、横竖屏和断线恢复补充可访问性验收。

## 6. 建议新增的验收场景

- 缺预算：Agent 必须先问预算，不直接给最终推荐。
- 有明确硬约束：推荐卡必须显示满足和未满足项。
- 演示报价：价格旁明确“演示，不可购买”，不能出现可购买暗示。
- 加入待购：取消确认后后端没有写入；确认后可撤销。
- 过期报价：按钮只能“重新询价”，不能加入待购。
- 比较：取消一个候选后决策页数量和内容立即一致。
- 保存：保存成功有就地反馈，重复点击不产生重复条目。
- 断线：在检索/审批/写入前后断网，恢复后任务状态不丢、不重复执行。
- 商家跳转：展示商家和域名，链接不安全或过期时阻断。

## 7. 审计边界

本次审计使用的是当前模拟器安装包与 fixture API 的真实点击证据；没有把 fixture 价格当作真实商业报价，也没有宣称真实联盟或生产可购买能力。当前证据能确认前端状态和调用路径，不能替代真实 MiMo 全量评测、真实商家报价或人工可用性研究。
